# chirp

A voice engine that serves many calls per process.

Each call is a WebSocket carrying 16 kHz mono PCM16 in and out, plus JSON
events. chirp listens (Silero VAD), decides when the caller has finished
(Smart Turn v3), transcribes and speaks through streaming services, handles
barge-in, and gets its answers from a pluggable **brain**: any streaming chat
backend, via a two-method trait.

```
caller audio ─► VAD (batched across calls) ─► end-of-turn model ─► STT commit
                                                                       │
caller ◄── audio ◄── TTS ◄── speakable text ◄── brain (your backend) ◄─┘
```

Status: early and private. See [PLAN.md](PLAN.md) for what "done" means and
how it is measured.

## Design

- **One process, many calls.** Tokio does only I/O. Model inference runs on
  dedicated threads: each VAD thread owns one Silero session and scores every
  call's 32 ms windows in batches; Smart Turn runs on its own small pool, only
  when a caller pauses.
- **Checked against the reference.** The models run through ONNX Runtime on
  the same files Pipecat ships (`models/fetch.sh` pins them by checksum).
  `tests/vad_parity.rs` and `tests/turn_parity.rs` compare framing, batching
  and features with Pipecat's Python outputs, generated by `scripts/` in the
  pinned `reference/` environment.
- **Barge-in** drops the spoken reply (closing its text-to-speech stream and
  any audio already queued) and tells the client to flush playback. The brain
  decides what happens to the work behind it.

## Run

```sh
./models/fetch.sh
ELEVENLABS_API_KEY=... CHIRP_BRAIN_KEY=... CHIRP_BRAIN_MODEL=... cargo run --release
cargo run --release --bin call_client -- ws://127.0.0.1:7861/v1/calls question.wav reply.wav
```

`CHIRP_BRAIN_URL` points at any OpenAI-compatible `/chat/completions` API
(default OpenAI). To answer with something else, implement `chirp::brain::Brain`
and serve calls with `chirp::call::run`.
